# 🧭 产品收敛与最终 TODO

> 这份文档定义 Yoyo 后续的功能边界、优先级和版本路线。以后新增、修改或删除功能，都应该先对照这里判断，而不是凭感觉扩散。

## 产品定义

Yoyo 是：

**一个面向办公与学习场景的桌面陪伴角色产品。**

她通过常驻桌面的轻互动、低打扰提醒和连续情绪反馈，让用户在工作过程中感到更轻松、更有陪伴感，而不是更分心。

## 最终目标

把产品收成一句话：

**Yoyo 是一个在你工作时陪着你的桌面小家伙。**

- [x] 统一 `Yoyo` 作为主角色的默认入口、资源路径和显示名

- [ ] 把形态切换从“兼容实现”继续推进成正式结构
- [ ] 清理角色 / 形态切换后的状态残留，避免动作、外观、特效串状态

### 2. 收敛产品主线

- [x] 在项目文档中明确产品定义
- [x] 把后续功能判断标准写入项目
- [ ] 所有新增功能只围绕工作场景下的陪伴感

### 3. 重构入口

- [x] 右键菜单重构为产品主线语言
- [x] 入口分成：`陪我一下 / 工作节奏 / 角色外观 / 小惊喜`
- [ ] 继续弱化不服务主线的零散入口

## P1 工作陪伴核心能力

### 1. 工作状态模式

- [x] 新增 `专注中 / 轻松工作 / 加班中 / 准备收工`
- [x] 模式切换接入菜单与设置
- [ ] 让模式更深入影响动作频率、提醒强度和语气

### 2. 关键提醒节点

- [x] 收敛提醒到开始工作、喝水、午饭、收工、收尾
- [x] 弱化泛提醒频率
- [ ] 继续清理与工作场景弱相关的提醒与播报

### 3. 收工反馈

- [x] 增加“今天辛苦了”入口
- [ ] 增加收工小结、轻庆祝、轻安抚
- [ ] 让收工反馈和当天状态、陪伴记录关联

### 4. 可见的关系反馈

- [ ] 让用户更容易感知 Yoyo 对自己状态的判断
- [ ] 增加“今天怎么看你”的一句反馈
- [ ] 让记忆和关系不只存在于底层数据

## P1 高频互动打磨

### 1. 待机

- [ ] 安静但不死板
- [ ] 有生命感，但不乱动、不抢视线

### 2. 抚摸

- [ ] 递进反馈更明显
- [ ] 连续互动更像关系回馈，而不是单次触发

### 3. 打字陪伴

- [ ] 更像陪着工作，而不是打断
- [ ] 减少工具感，增加陪伴感

### 4. 跟随

- [ ] 轨迹更柔和
- [ ] 减少“窗体在追鼠标”的生硬感

### 5. 特效收敛

- [x] 分身特效重做
- [ ] 控制高频特效的触发频率和时长
- [ ] 只保留高质量惊喜感，不堆炫技

## P1 外观系统重构

### 最终方向

从“复杂配件系统”改成“高完成度套装系统”。

### 1. 保留随机换装

- [x] 保留随机换装能力
- [x] 随机对象改为整套造型，而不是配件自由叠加

### 2. 去掉复杂选项

- [x] 去掉分层手动组合入口
- [x] 弱化低完成度、易冲突的自由搭配系统

### 3. 改成套装选择

- [x] 提供少量高完成度套装：
  - [x] 日常
  - [x] 温暖
  - [x] 小披风
  - [x] 节日
  - [x] 开心庆祝装

### 4. 保留 3 个入口

- [x] 随机换装
- [x] 选择套装
- [x] 恢复默认

## 每次改功能前都先问

1. 这个功能是不是让 Yoyo 更像“工作时陪着你的桌面小家伙”？
2. 它会不会让产品更乱、更吵、更像别的品类？
3. 它是在强化主线，还是在继续做散？

如果第 1 个回答不够强，或者第 2 / 第 3 个偏负面，就不应优先开发。
